# Сравнение large-v3-turbo-q5_0 (текущая) vs large-v3 на архиве диктовок

## Контекст

Сейчас активна `large-v3-turbo-q5_0` — квантованная turbo-версия (урезанный до 4 слоёв декодер). Ранее в сессии выяснили, что у turbo-архитектуры документированно более слабый language-ID на языках с меньшим объёмом обучающих данных (это касается ru/uk). Пользователь хотел сравнить текущую модель с `large-v3` и `large-v3-turbo-q8_0`.

**Анализ, представленный пользователю и подтверждённый им:** `large-v3-turbo-q8_0` отличается от текущей модели только точностью квантования (5→8 бит) при той же архитектуре и весах — эффект предсказуемый и, скорее всего, малозаметный. `large-v3` — другая архитектура декодера (32 слоя вместо 4, без квантования) — единственное сравнение, способное реально повлиять на качество ru/uk. **Решение пользователя: сравнивать только текущую модель против `large-v3`, без q8_0.**

Цель эксперимента — понять, стоит ли `large-v3` (медленнее, тяжелее, 2.9 ГиБ) той разницы в качестве, которую она даёт на реальных диктовках пользователя, особенно на code-switching (ru + технический английский жаргон) и в сложных случаях (шум, клиппинг, тишина).

## Что уже выяснено разведкой

- В проекте уже есть неисполненный план [plans/quality-regression-test.md](quality-regression-test.md) с методологией воспроизведения поведения приложения на архиве (порт `splitAtSilence`, посегментные вызовы `whisper-cli`). Этот план — про другие параметры (streaming, prompt), не про модели, но его архитектура прогона переиспользуется здесь.
- `~/.local-whisper/voice-archive/` — не единый файл на диктовку, а директория `chunk_NNN.wav` (по 1с, 16kHz mono PCM16) на сессию, имя `<YYYYMMDD>_<HHMMSS>_g<gen>`. Хранится 2-3 дня (авто-чистка при старте Hammerspoon), сейчас 144 директории, ~85 минут аудио, диапазон 2026-08-28 — 2026-08-31.
- Весь текущий архив записан и транскрибирован уже на `large-v3-turbo-q5_0` (подтверждено логом и датой файла модели) — второй модели для сравнения там нет и быть не может, её нужно скачать и прогнать заново по этим же аудио.
- Разметки/эталонных транскриптов в архиве нет. Но у 4 сессий есть **проверяемый эталон**: `~/.local-whisper/recent.json` хранит последние 10 диктовок, и по метке времени они точно сопоставляются с директориями архива (это то, что реально было вставлено в текст на `q5_0`).
- **Пробел:** в архиве не нашлось ни одного украинского фрагмента (только русский + один английский клип + смешанная ru/en техническая лексика). Если украинское покрытие важно — потребуется отдельно надиктовать 1-2 тестовых клипа; в текущий эксперимент это не включаю, но явно отмечу пробел в отчёте.
- `FINAL_SEGMENT_SECS = 55` в [hammerspoon/init.lua](../hammerspoon/init.lua) — 3 из выбранных сессий длиннее этого порога и в проде были бы порезаны `splitAtSilence`; чтобы тест точно воспроизводил поведение приложения, harness обязан резать точно так же, а не скармливать длинные сессии целиком одним файлом.

## Harness

Новая папка `tests/model-comparison/` (по аналогии с `tests/quality-regression/` из неисполненного плана, но отдельная — другой эксперимент).

1. **`build_segments.py`** — на вход директория архива. Порт `splitAtSilence`/`getWavRMS` из `init.lua` (1:1: RMS по 16-бит PCM, группировка с потолком 55с, откат к самому тихому чанку в последних 8с окна). Для сессий короче 55с — тривиально один сегмент. Продукт: `tmp/<session>/seg_NN.wav` через `ffmpeg -f concat -safe 0` (как делает `dispatchSegment`) — **один раз на сессию**, независимо от количества моделей, чтобы оба прогона получали побайтово идентичный звук.
2. **`run_comparison.sh`** — для каждой сессии, для каждой из двух моделей (`large-v3-turbo-q5_0`, `large-v3`), для каждого сегмента: `~/whisper.cpp/build/bin/whisper-cli -m <model-path> -f <segWav> -l auto -nt` (точно те же флаги, что в `dispatchSegment`; `--prompt` не добавляется — файл `~/.local-whisper/prompt` сейчас пуст, как и в проде). Склеивает тексты сегментов по порядку, засекает суммарное wall-time на сессию.
3. **`report.py`** — собирает `results/summary.md`:
   - на сессию: длительность, причина отбора, эталон из `recent.json` (если есть);
   - на модель: итоговый текст, суммарное время, языки по сегментам;
   - word-level Levenshtein: q5_0 против large-v3 (величина расхождения — сигнал, какие сессии смотреть внимательнее глазами), и каждая модель против эталона там, где он есть (сверка, что офлайн-прогон `q5_0` воспроизводит то, что реально вставилось в проде);
   - явная пометка: "ни одного uk-фрагмента в выборке нет".
4. После генерации отчёта — **обязательный ручной проход**: читаю оба транскрипта по каждой сессии рядом, отдельно отмечаю: правильность имён собственных и жаргона (Cloud MD/CLAUDE.md, Payoneer, PayPal), поведение на тишине/клиппинге, есть ли реальная разница в code-switching ru/en. Численная метрика Левенштейна показывает *где* есть расхождение, не показывает *кто прав* — это может увидеть только чтение.
5. Время выполнения репортится отдельной заметной строкой в отчёте: `large-v3` (32-слойный декодер, без квантования) ожидаемо в разы медленнее `large-v3-turbo-q5_0` — это прямое противоречие с целью проекта («время ожидания после диктовки не должно расти» — см. AGENTS.md), так что даже при лучшем качестве `large-v3` может быть неприменима для live-режима — стоит явно посчитать во сколько раз медленнее, а не просто отметить факт.

`tmp/` добавляется в `.gitignore` (только промежуточные WAV, не в git). Скрипты и `results/summary.md` — в git, в проекте.

## Как выполняется (явно, по требованию пользователя)

Никаких Workflow-оркестраций, никакого запуска в изолированном worktree/sandbox, никакой фоновой раздачи задач субагентам для самого прогона. Всё — обычные shell/python-скрипты, которые лежат в `tests/model-comparison/` в реальном чекауте проекта и выполняются напрямую через Bash-доступ агента внутри Claude Code: `download-ggml-model.sh`, `build_segments.py`, `run_comparison.sh`, `whisper-cli`, `report.py` — каждый запускается как обычная команда в терминале, результаты пишутся на диск в тот же `tests/model-comparison/results/`, никакой скрытой инфраструктуры. Долгие прогоны идут через фоновый Bash (`run_in_background`), чтобы не блокировать сессию, но это тот же самый терминал, не отдельный агент/песочница.

## Порядок выполнения (после выхода из plan mode)

1. Скачать `large-v3` (2.9 ГиБ): `cd ~/whisper.cpp && bash ./models/download-ggml-model.sh large-v3`. Диска достаточно (60 ГиБ свободно).
2. Написать `build_segments.py`, `run_comparison.sh`, `report.py` в `tests/model-comparison/`.
3. Прогнать на 15 отобранных сессиях × 2 модели (в фоне — `large-v3` без квантования будет заметно медленнее `q5_0`, счёт может идти на минуты на сессию для длинных записей).
4. Сгенерировать `results/summary.md`, прочитать транскрипты глазами, дописать в отчёт качественные наблюдения (жаргон/имена собственные/code-switching/устойчивость к шуму) и явный вывод: стоит ли переключаться, с оговоркой про скорость.
5. Прислать одну ссылку на `tests/model-comparison/results/summary.md`.

## Что НЕ делаю

- Не трогаю `hammerspoon/init.lua`, `tools/lw-record.swift`, `tools/transcribe.sh`, `~/.local-whisper/model` — рабочая конфигурация утилиты не меняется.
- Не скачиваю и не тестирую `large-v3-turbo-q8_0` (решение пользователя — не входит в эксперимент).
- Не удаляю и не переименовываю файлы в `voice-archive/` — только чтение.
- Не записываю новые тестовые клипы (в т.ч. украинские) без отдельного запроса — только отмечаю пробел в отчёте.

## Проверка результата

Итог — файл `tests/model-comparison/results/summary.md` с текстами обеих моделей по каждой из 15 сессий, таблицей метрик (время, Левенштейн-расхождение, сверка с эталоном) и written-выводом. Пользователь сам решает по прочтении, переключаться ли на `large-v3`, с учётом trade-off по скорости, который будет явно посчитан в отчёте.

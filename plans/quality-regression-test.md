# Тест локальной whisper-модели на архивных диктовках

## Что тестируем и почему именно это

За последний месяц в тракте «аудио → текст» менялись семь параметров. Все правки — в [hammerspoon/init.lua](../hammerspoon/init.lua), кроме микрофона (он в [tools/lw-record.swift](../tools/lw-record.swift)). Каждый тест ниже отвечает на вопрос «был ли этот параметр причиной падения качества?».

| # | Параметр | Как было | Как сейчас | Коммит | Проверяемо на архиве |
|---|---|---|---|---|---|
| 1 | `--carry-initial-prompt` | добавлен 17 авг | убран 27 авг | 970047d → 6703706 | да |
| 2 | Автосев файла-образца при первом запуске | добавлен | убран 27 авг | 970047d → 6703706 | да |
| 3 | Содержимое `~/.local-whisper/prompt` | суржиковый RU/UK/EN с терминами | **пустой** (0 байт) | операционно | да |
| 4 | Стриминг: сегменты уходят в whisper во время записи | одна финальная транскрипция после отпускания клавиши | во время + догон в конце, каждый сегмент — отдельный вызов whisper-cli, контекст между сегментами не передаётся | 9ceaf1a | да |
| 5 | `splitAtSilence`: где резать сегмент | не резался (либо резался жёстко по индексу) | по тишине, потолок 55 с | 970047d | да |
| 6 | Авто-детект языка на каждом сегменте | язык определялся один раз | на каждом сегменте заново | 970047d | да |
| 7 | Микрофон: ffmpeg → нативный Swift-рекордер | ffmpeg avfoundation (терял ~10% аудио) | `lw-record.swift`, AVAudioConverter с дефолтным качеством | 970047d | **нет** |

**Почему #7 не тестируется на архиве.** В `~/.local-whisper/voice-archive/` уже лежит то, что записал именно Swift-рекордер. Проверить, лучше ли ffmpeg-версия, можно только записав одну и ту же речь заново обоими способами живьём. Это отдельная задача, в этот план не включена.

**Что не меняем в тестах.** Модель `large-v3-turbo-q5_0` — та единственная, что вы используете (`~/.local-whisper/model`). Язык `auto` — как в `~/.local-whisper/lang`. Вывод не тестируем, потому что paste/type/copy на качество распознавания не влияют.

## Как воспроизводим то, что делает утилита

Приложение **не склеивает чанки в один WAV**. Оно нарезает поток на сегменты по паузе (функция `splitAtSilence`), сегмент по границе 55 секунд отправляет в whisper-cli отдельным вызовом, и итоговый текст собирается из ответов whisper по номеру сегмента.

Значит основной режим теста — **тот же**: беру чанки из архивной сессии, применяю ту же логику `splitAtSilence` (переношу её из `init.lua` один-в-один), отдаю каждый сегмент whisper-cli отдельным вызовом. Никакого «склеить всё в один WAV» в основном тесте нет.

Один-единственный контрольный вариант, где всё-таки склеивается всё в один файл, — только для теста параметра #4 (стриминг): «а что если бы утилита не резала, а транскрибировала одним куском?». Это единственный способ увидеть, вносит ли сама стриминговая нарезка потерю качества на швах между сегментами. Никаких других применений склейки нет.

## Скрипты

### `simulate_app.sh` — то, что делает утилита сейчас

Вход: путь к сессии архива (`~/.local-whisper/voice-archive/20260828_143012_g4/`).

Что делает:
1. Читает чанки, применяет `splitAtSilence` (порт функции из `init.lua`, потолок 55 с) — получается 1..N групп чанков.
2. Для каждой группы делает временный WAV через `ffmpeg -f concat -safe 0` (это то же, что делает утилита в `dispatchSegment`).
3. Для каждой группы отдельно вызывает `~/whisper.cpp/build/bin/whisper-cli -m ~/whisper.cpp/models/ggml-large-v3-turbo-q5_0.bin -f <wav> -l auto -nt` с заданными дополнительными флагами.
4. Склеивает тексты по порядку сегментов.

Именно этот скрипт — «эталон» того, как звучит утилита сегодня.

### `test_matrix.sh` — прогон интересных комбинаций

На вход берёт список сессий (выбираю сам, см. ниже). Для каждой сессии прогоняет через `simulate_app.sh` **пять вариантов**, отличающихся только одним параметром за раз:

| Вариант | #1 carry | #3 промпт | #4 стриминг-нарезка | #6 язык |
|---|---|---|---|---|
| **сейчас** (base) | нет | пусто | как в утилите (splitAtSilence, 55с) | auto на каждом сегменте |
| **+короткий промпт** | нет | RU-семпл из прошлого исследования | как в утилите | auto на каждом |
| **+короткий промпт +carry** | да | тот же RU-семпл | как в утилите | auto на каждом |
| **+короткий промпт, whole-file** | нет | тот же RU-семпл | **один вызов whisper-cli на всю запись** | один auto-детект на всё |
| **+короткий промпт, зафиксированный язык** | нет | тот же RU-семпл | как в утилите | язык фиксируется по первому сегменту |

Каждый вариант меняет ровно одну переменную относительно варианта выше. Это позволит увидеть вклад каждого параметра отдельно, не смешивая.

**Не тестирую здесь:** параметр #5 (`splitAtSilence` vs фикс-индекс) — потому что «как было раньше» в этой версии кода вообще не было (резалось иначе), корректный контроль поставить не получится без правки-возврата в коде. Про это — отдельным пунктом в отчёте, а не в матрице.

### `score.sh` — сравнение с текстом из recent.json

Для сессий, у которых нашёлся текст в `~/.local-whisper/recent.json` по совпадению времени (Unix time ≈ имя папки), считает расстояние Левенштейна на словах между каждым вариантом и текстом из recent.json. Это грубая метрика — recent.json содержит то, что реально вставилось в приложение, а не «эталон». Использую только для указания на явные регрессы, а не как истину.

### `report.sh` — сборка отчёта

Складывает всё в `tests/quality-regression/results/summary.md`:

- Для каждой из выбранных сессий: длительность, дата, ссылка на архив, текст из recent.json (если найден).
- Для каждого варианта — итоговый текст, время выполнения, число сегментов, определённые языки по сегментам, Левенштейн против recent.json.
- Внизу — компактная таблица «параметр × сессия → метрика» + мой человеческий вывод из 5–10 предложений: что дало эффект, что нет.

## Какие сессии беру

- 2 короткие (13–30 с) — быстрый сигнал на «word-salad» от пустого промпта.
- 2 средние (60–100 с) — здесь границы сегментов 55 с начинают резать; тут будет виден вклад параметров #4 и #6.
- 2 длинные (100–157 с) — многосегментные, максимальная разница между «сейчас» и «whole-file».
- Из этих шести — минимум две пары с текстом в recent.json для сравнения.
